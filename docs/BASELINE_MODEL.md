# BaselineEngine 决策模型说明

## 1. 目标与边界

BaselineEngine 是一个可解释、可复现、参数可训练的立直麻将基线。它的目标不是立刻达到高段位水平，而是提供一个稳定参照：每个动作必须合法，每个切牌都有完整特征和分数，权重改变不要求修改规则代码。

当前版本支持四人麻将的完整模拟闭环，采用 RiichiEnv 的雀魂规则预设。已实现和牌、立直、切牌、立直后严格摸切、等待不变暗杠与保守跳过；未立直时的吃、碰和杠暂不主动选择。三麻的拔北与三麻牌效率尚未纳入本版本。

## 2. 模块边界

```text
Observation
   │
   ├─ state.py      只提取公开状态
   ├─ features.py   只编排各特征提取器
   ├─ efficiency_features.py  向听数和有效牌
   ├─ lookahead_features.py   公开信息一巡Expectimax
   ├─ shape_features.py       不重叠牌形
   ├─ value_features.py       宝牌和役潜力
   ├─ risk_features.py        危险度和局面倍率
   ├─ feature_registry.py     特征名称、分组和归一化尺度
   ├─ scoring.py    执行归一化后的分组加权
   ├─ engine.py     只负责动作优先级和选择
   └─ decision.py   保存候选、贡献值和解释

configs/baseline.yaml
   └─ config.py     严格加载、类型转换和字段校验
```

规则、特征和权重有意分离：规则决定动作是否参与比较；特征描述动作造成的状态变化；权重表达特征的重要程度。

所有特征元数据只在`feature_registry.py`登记一次。配置严格校验、归一化、分组评分和按组启停均读取该注册表。新增特征不再需要在配置加载器、评分器和引擎中分别维护名称列表。

## 3. 硬规则决策顺序

引擎首先读取 `observation.legal_actions()`，随后按固定优先级选择：

1. 存在荣和或自摸时直接和牌。
2. 已经立直且存在等待不变暗杠时选择暗杠。
3. 已经立直且需要切牌时强制摸切，不进入线性评分。
4. 存在立直动作时直接立直；声明后的舍牌必须保持听牌。
5. 存在普通切牌动作时进入线性评分。
6. 响应他家舍牌时，如存在跳过，则保守跳过。
7. 如果以上均不适用，选择第一个合法动作作为防崩溃回退。

硬规则不会与切牌分数混合，因此有效牌分数不可能覆盖和牌动作。`always_win`、`always_riichi` 和 `conservative_calls` 位于配置文件的 `policy` 段，可以在后续版本替换为更细致的策略模块。

## 4. 切牌状态构造

对每个合法切牌动作，删除对应的136编码实体牌，得到切牌后的13张手牌。公开状态包含：

- 自家手牌；
- 四家牌河；
- 所有公开副露；
- 宝牌指示牌；
- 四家立直状态。

这些牌共同形成34种牌的可见数量。有效牌剩余枚数按 `4 - visible_count` 估计。未知的对手手牌不会被错误地计入可见数量。

## 5. 向听数与有效牌

向听数由 RiichiEnv 的 `calculate_shanten()` 计算。该函数覆盖普通形、七对子和国士无双的最短向听路径。

对于每一种尚未全部可见的牌，向切牌后手牌加入一张代表牌：如果向听数下降，则它是有效牌。

保存两个特征：

- `ukeire_types`：有效牌种类数；
- `ukeire_count`：根据公开信息估算的有效牌剩余总枚数。

向听数不再是线性权重。候选动作先按向听数进行硬排序，只有向听数相同时才比较可训练分数，因此训练过程不会意外学出“为保留宝牌主动退向听”。后续若需要完全弃和，应增加独立攻守策略，而不是让线性参数破坏牌效率约束。

## 6. 基础牌形特征

牌形扫描在万、筒、索三门内分别进行：

- `ryanmen`：相邻且不是12、89的搭子；
- `penchan`：12或89搭子；
- `kanchan`：间隔一张的搭子；
- `pair`：对子数量；
- `value_honor_pair`：三元牌对子数量。

这是轻量启发式，不尝试对整副手牌做最优面子分解，因此复合形可能贡献多个局部特征。该行为是确定性的，后续可用训练权重校准，也可以替换成完整牌形分解器。

役牌对子覆盖：

- 白、发、中；
- 当前场风；
- 当前自风。

自风按 `(player_id - dealer) mod 4` 推导，0～3依次代表东、南、西、北。场风和自风相同时使用集合去重，因此东场东家的东对子只作为一个役牌对子特征，不会被错误计算两次；实际两番价值可在未来的精确打点模块中表达。

## 7. 立直后的严格动作

引擎自身保存立直声明阶段，并执行三项约束：

1. 选择立直后，下一次舍牌只从仍为听牌的候选中选择。RiichiEnv 在立直中间阶段会提供全部舍牌，因此不能只依靠合法动作列表。
2. 正式立直后，如果不能和牌或暗杠，直接切出手牌列表末尾的实体摸牌，不再进行牌效率评分。
3. 正式立直后只接受 RiichiEnv 暴露的暗杠动作。

RiichiEnv 对立直暗杠做了严格验证：移除本巡摸牌得到杠前手牌和等待集合；将四张同种牌转换为暗杠副露得到杠后手牌和等待集合；只有两边等待集合完全相同且不为空时，`ANKAN` 才会成为合法动作。BaselineEngine 不自行近似该规则，而是只消费这一经过规则引擎确认的动作。

## 8. 未使用牌价值

旧版独立孤张扫描已经移除。当前模型先完成不共享牌的全手结构分解，再将没有进入完整面子、雀头或必要搭子的牌按位置分为：

- 中张3～7；
- 近幺九2、8；
- 幺九1、9；
- 字牌。

这些字段使用负权重。中张惩罚较轻，因为它更容易形成后续连接；幺九和字牌惩罚更重。同一张牌不会同时获得搭子价值和未使用牌惩罚。

## 9. 宝牌与赤牌

引擎根据宝牌指示牌计算实际宝牌，正确处理：

- 9循环到1；
- 北循环到东；
- 中循环到白。

切牌后仍保留的每张普通宝牌产生 `retained_dora` 特征，每张赤五产生 `retained_red` 特征。使用“保留价值”而不是“切出惩罚”，可以让特征保持对切牌后状态的统一描述。

## 10. 基础危险度

只有存在对手立直时才产生风险。当前实现按以下顺序判断：

1. 该牌对所有立直者均为现物：风险为0；
2. 字牌按全局可见数量降低风险；
3. 数牌按幺九、近幺九、中张给出基础风险。

多家立直时，只有对全部立直者都是现物才算完全安全。当前尚未实现筋、壁、序盘舍牌模式、立直宣言牌周边以及副露读牌，因此危险度是保守基线而非精确放铳率。

## 11. 分组归一化评分

所有切牌使用同一公式：

```text
score(action) = Σ normalized_feature[action, i]
                  × feature_weight[i]
                  × group_weight[group(i)]
```

当前特征包括：

```text
ukeire_count, ukeire_types,
ryanmen, kanchan, penchan, pair, value_honor_pair,
retained_dora, retained_red,
unused_middle, unused_near_terminal,
unused_terminal, unused_honor,
discard_risk,
yaku_yakuhai_delta, yaku_tanyao_delta,
yaku_chiitoitsu_delta, yaku_flush_delta
```

四项役特征均为动作前后潜力差，而不是动作后的绝对役价值。详细算法、配置和限制见 `docs/YAKU_VALUE_MODEL.md`。

特征分为四组：

- `efficiency`：有效牌枚数与种类；
- `value`：宝牌、赤牌和役潜力；
- `shape`：搭子、对子与孤张结构；
- `risk`：弃牌危险度。

有效牌、手牌计数和役潜力分别按配置中的尺度归一化。危险度还会乘以巡目、立直者数量、庄家威胁、自身向听以及高价值手牌倍率。早巡风险较低，晚巡风险较高；自身听牌或高价值时风险惩罚适当降低。

决策记录同时保存原始特征、归一化特征、逐特征贡献和四组贡献。这使训练器可以区分输入尺度变化与权重变化，也可以先只搜索四个模块级权重，再逐步开放细粒度参数。

同分时按动作的 MJAI 字符串排序，保证相同状态、相同配置总会得到相同动作。

硬规则决策会记录不同的 `policy` 名称，例如 `riichi_tsumogiri`、`riichi_wait_preserving_ankan` 和 `riichi_tenpai_discard`，便于后续统计每类决策。

## 12. 决策记录

`BaselineEngine.last_decision` 保存最近一次决策：

- 使用的策略分支；
- 最终动作；
- 全部切牌候选；
- 每个候选的总分；
- 原始特征；
- 每个特征的分数贡献；
- 向听数、有效牌和危险度；
- 面向用户的简短原因。

训练数据应保存全部候选，而不只是最终动作。未来可以用监督牌谱做动作排序，也可以用模拟结果通过 CMA-ES、贝叶斯优化或排序学习拟合权重。

## 13. 配置约束

`configs/baseline.yaml` 当前使用版本4。加载器执行严格校验：

- 未知字段直接报错；
- 缺少权重直接报错；
- 所有权重必须是有限数值；
- 危险度必须位于0到1；
- 归一化尺度和风险倍率必须为正数；
- 不支持的配置版本拒绝加载。

这样可以避免训练脚本拼错参数名后静默使用错误配置。

## 14. 已知限制与推荐迭代顺序

建议按以下顺序扩展：

1. 筋、壁和多家威胁合并风险；
2. 立直与默听比较；
3. 有役保证下的吃碰；
4. 未立直时的暗杠、加杠决策；
5. 完整牌形分解和役种潜力；
6. 精确处理连风牌对子潜在两番价值；
7. 点棒、巡目和顺位驱动的攻守模式；
8. 将决策记录写入训练数据集并自动优化权重。

在增加新特征时，应同步增加配置字段、严格校验、单元测试和本文件说明。

## 15. 运行与验证

```powershell
.\.venv\Scripts\python scripts\smoke_baseline.py
.\.venv\Scripts\python -m pytest -q
```

示例脚本让四个 BaselineEngine 完成一局，并将可回放 MJAI 日志写入 `artifacts/replays/baseline-smoke.jsonl`。
