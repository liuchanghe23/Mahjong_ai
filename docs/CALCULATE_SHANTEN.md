# `calculate_shanten()` 覆盖范围说明

## 1. 先澄清：它不计算役种

`riichienv.calculate_shanten(hand_tiles)` 计算的是手牌距离某种合法和牌结构还差多少张，不判断这副牌是否有役，也不计算番数、符数和点数。

因此“它覆盖哪些役种”这个问题，准确答案是：**它不覆盖任何役种判定**。

例如下面这些役都不由 `calculate_shanten()` 判断：

- 立直、双立直、一发、门前清自摸和；
- 断幺九、平和、一杯口、二杯口；
- 役牌、场风、自风；
- 三色同顺、一气通贯、混全带幺九、纯全带幺九；
- 对对和、三暗刻、三杠子、三色同刻、小三元、混老头；
- 混一色、清一色；
- 岭上开花、抢杠、海底摸月、河底捞鱼；
- 所有役满，例如国士无双、四暗刻、大三元、字一色、绿一色、清老头、小四喜、大四喜、四杠子、九莲宝灯、天和、地和。

其中“国士无双”虽然在结构向听计算中被覆盖，但这不等于函数完成了役满成立判定。它只知道手牌距离国士的基本牌形还有多远。

## 2. 实际覆盖的三类和牌结构

函数比较三条结构路径，并返回最接近和牌的一条。

### 2.1 标准型：四面子一雀头

标准和牌形由以下部分组成：

```text
面子 + 面子 + 面子 + 面子 + 雀头
```

面子可以是：

- 顺子，例如123万；
- 刻子，例如777筒。

雀头是一对相同的牌。标准型向听计算只关心面子、搭子和雀头组合，不关心这些组合最终形成什么役。

因此它能为平和、断幺九、三色同顺、一气通贯、混一色等大量手牌提供正确的“结构距离”，但不会告诉调用者具体是哪一种役，也不会保证最终有役。

### 2.2 七对子型

七对子基本结构是七组不同的对子：

```text
对子 × 7
```

函数会考虑手牌距离七对子结构的距离，并与标准型向听比较。

需要注意：

- 四张相同的牌不能简单当作两个独立对子；
- 七对子必须满足七种不同牌的要求；
- 函数只计算结构距离，不计算七对子二番，也不检查其他同时存在的役。

### 2.3 国士无双型

国士无双使用13种幺九牌：

```text
1m 9m 1p 9p 1s 9s E S W N P F C
```

基本结构要求：

- 13种幺九牌全部出现；
- 其中任意一种再有一张作为对子。

函数会计算缺少多少种幺九牌以及是否已经有对子，从而得到国士路径的向听数。

它不会区分：

- 普通国士无双等待；
- 国士无双十三面听；
- 某个平台是否把十三面听计为双倍役满。

这些属于和牌、役种与规则判定，应交给 `HandEvaluator` 和对应规则配置。

## 3. 返回值含义

常见返回值：

| 返回值 | 含义 |
|---:|---|
| `-1` | 手牌已经形成完整和牌结构 |
| `0` | 听牌，再得到一张有效牌即可形成和牌结构 |
| `1` | 一向听 |
| `2` | 二向听 |
| 更大 | 距离目标结构更远 |

“形成和牌结构”不等于“可以合法和牌”。例如一副副露后没有任何役的完整牌形，结构上可以是 `-1`，但实战中仍然不能荣和或自摸。

## 4. 函数不知道的上下文

`calculate_shanten()` 的输入只有手牌实体牌ID列表，因此它不知道：

- 当前场风和自风；
- 是否门清、是否立直；
- 是否一发、岭上、抢杠、海底或河底；
- 宝牌、里宝牌和赤宝牌；
- 玩家是否振听；
- 当前摸牌还是荣和牌；
- 副露来源与开闭状态；
- 平台规则和双倍役满规则；
- 点棒、本场和供托。

这些信息不应强行塞进向听函数，而应由更高层的状态、役种和计分模块处理。

## 5. 与 BaselineEngine 的关系

BaselineEngine 使用它完成两件事：

1. 对每个切牌候选计算切牌后的向听数；
2. 尝试加入每一种牌，如果向听数下降，就把该牌视为有效牌。

伪代码如下：

```python
current = calculate_shanten(hand_after_discard)

for tile_kind in all_34_tile_kinds:
    trial = hand_after_discard + [one_tile_of(tile_kind)]
    if calculate_shanten(trial) < current:
        effective_tiles.add(tile_kind)
```

役牌价值、宝牌价值、牌形质量和危险度由 BaselineEngine 的其他特征负责，不能从向听数函数中得到。

## 6. 与 `HandEvaluator` 的职责区别

需要判断实际和牌及役种时，应使用 RiichiEnv 的 `HandEvaluator`：

```python
from riichienv import HandEvaluator

evaluator = HandEvaluator.hand_from_text("111m33p12s111666z")
is_tenpai = evaluator.is_tenpai()
waits = evaluator.get_waits()
result = evaluator.calc(win_tile, dora_indicators=[], ura_indicators=[])
```

`result` 才会提供：

- 是否实际可和；
- 是否役满；
- 番数和符数；
- 荣和、亲家自摸、子家自摸点数；
- 役种ID和役种名称。

简化理解：

```text
calculate_shanten()：距离某种和牌结构还有多远
HandEvaluator：这次是否真的能和、有什么役、值多少点
```

## 7. 四麻与三麻

四人麻将使用：

```python
calculate_shanten(hand_tiles)
```

三人麻将应使用：

```python
calculate_shanten_3p(hand_tiles)
```

三麻通常移除二万到八万，因此某些在四麻中可形成的万子进张在三麻中不存在。若三麻仍调用四麻函数，可能得到不符合实际牌山的向听路径。

## 8. 使用时的常见误区

### 误区一：向听更低就一定是最佳打法

向听数不考虑有效牌剩余枚数、打点、安全度和顺位。同为一向听，4枚有效牌和20枚有效牌的质量差异很大。

### 误区二：返回 `-1` 就一定能点击和牌

错误。完整结构仍可能无役、振听或不满足平台规则。

### 误区三：它能判断平和或七对子役

它能识别七对子结构路径，但不执行役种判定；标准型结构也不会被标记为平和。

### 误区四：宝牌会降低向听数

宝牌只增加打点，不改变和牌结构，因此不会影响向听数。

### 误区五：所有规则差异都体现在向听数里

向听数主要描述牌形距离。责任支付、双倍役满、抢暗杠国士等平台差异属于规则和计分层。
